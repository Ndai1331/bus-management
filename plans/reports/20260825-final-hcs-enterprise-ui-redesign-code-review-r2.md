# Final code review — HCS enterprise UI redesign (r2)

## Actionable findings

- **P1 — Mobile drawer focus isolation is incomplete.** `src/HCS.Blazor.Client/Layouts/HCSMainLayout.razor:16,225-237` leaves the skip link, the focusable backdrop button, `NotificationToast`, and the trailing UI alerts outside the `inert` regions. `NotificationToast` is rendered at `src/HCS.Blazor.Client/Layouts/HCSMainLayout.razor:231-234` and has a fixed `z-index: 1080` at `src/HCS.Blazor.Client/Components/NotificationToast.razor.css:1-10`, so a toast can remain tabbable and visually above the drawer while navigation is open. Add a single inert background scope (or an equivalent focus trap/`aria-hidden` strategy) covering every non-drawer sibling, and keep focus cycling inside the drawer/toggle until close.

- **P2 — Tablet chat full-bleed reset is still lost to CSS specificity.** The tablet reset at `src/HCS.Blazor.Client/Layouts/HCSMainLayout.razor.css:212-224` uses `.hcs-main-content:has(.hcs-chat-page)`, while `src/HCS.Blazor.Client/wwwroot/main.css:385-393` uses the higher-specificity `.hcs-app-shell .hcs-main-content:has(.hcs-chat-page)` and restores `padding: 1.5rem ...`. The later override in `src/HCS.Blazor.Client/wwwroot/hcs-components.css:711-716` only applies below `767.98px`; at 768–1100px the chat remains inset and loses the required full-bleed layout. Add an equal/higher-specificity `padding: 0` override for the full tablet breakpoint or consolidate the competing rule.

- **P2 — Focus-ring styling is not token-consistent.** `src/HCS.Blazor.Client/wwwroot/hcs-tokens.css:69` defines `--hcs-focus-ring`, but the generic rule at `src/HCS.Blazor.Client/wwwroot/hcs-components.css:28-32` uses a separate outline, catalog fields retain the old blue ring at `src/HCS.Blazor.Client/wwwroot/main.css:1102-1106`, signature selects retain blue outlines at `src/HCS.Blazor.Client/Components/UserSignaturesPanel.razor.css:61-65`, and the newly added signature override hard-codes another teal ring at `src/HCS.Blazor.Client/Components/UserSignaturesPanel.razor.css:495`. The language-menu item rule at `src/HCS.Blazor.Client/Layouts/CultureSelector.razor.css:97-102` also suppresses its outline without applying the token ring. Replace these local colors/outline resets with one token-driven focus treatment so keyboard focus is consistently visible.

- **P2 — The strict no-gradient direction is still violated in application pages.** Decorative gradients remain at `src/HCS.Blazor.Client/Pages/Index.razor.css:9`, `src/HCS.Blazor.Client/Pages/AccountManagement.razor.css:30`, and the account skeleton shimmer at `src/HCS.Blazor.Client/Pages/AccountManagement.razor.css:397`. Replace them with solid surfaces and opacity-based loading states, or explicitly narrow the no-gradient acceptance criterion.
